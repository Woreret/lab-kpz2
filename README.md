# Лабораторна робота №2. Варіант 3

Тема роботи — функціональна парадигма в Python. Предметна область варіанта 3 — позиції замовлень.

У роботі є дві основні частини:

1. Обробка файлу із замовленнями у функціональному стилі.
2. Калькулятор арифметичних виразів на основі `match/case` і рекурсії.

Потрібен Python 3.10 або новіший. Сторонні бібліотеки не потрібні.

## Запуск

Із папки проєкту:

```sh
python demo.py
```

У PowerShell також можна виконати:

```powershell
./run.ps1
```

## Загальний принцип роботи

Вхідні рядки проходять такий шлях:

```text
файл -> parse -> normalize -> keep -> aggregate -> результат
```

- `parse` розбирає рядок і відкидає неправильні дані;
- `normalize` приводить поля до однакового вигляду;
- `keep` залишає записи, у яких `qty >= 5`;
- `aggregate` групує записи за категорією та підсумовує `qty`.

Очікуваний результат для підготовленого файлу:

```python
{'електроніка': 31, 'книги': 23, 'одяг': 33}
```

## Пояснення кожного файла

### `data/orders.txt`

Це файл із вхідними даними. Один рядок описує одну позицію замовлення. Поля розділено символом `;`:

```text
sku;qty;price;category
```

Наприклад:

```text
BOOK-001;5;320;Книги
```

- `sku` — код товару;
- `qty` — кількість одиниць товару;
- `price` — ціна;
- `category` — категорія товару.

У файлі 20 рядків: 15 правильних і 5 навмисно неправильних. У неправильних рядках може бути порожнє поле, неправильна кількість, неправильна ціна або недостатня кількість полів. Це потрібно для демонстрації роботи `parse` і підрахунку помилок.

### `src/orders/model.py`

У цьому файлі описані структури даних.

`Result` зберігає результат функції `process`:

```python
@dataclass(frozen=True)
class Result:
    records: tuple[dict, ...]
    errors: int
```

- `records` — кортеж успішно розібраних записів;
- `errors` — кількість неправильних рядків.

`Record` представляє одну позицію замовлення:

```python
@dataclass(frozen=True, slots=True)
class Record:
    sku: str
    qty: int
    price: float
    category: str
    received_at: float
```

`@dataclass` автоматично створює конструктор, порівняння об'єктів та їх зручне текстове представлення. `frozen=True` забороняє змінювати поля після створення об'єкта. `slots=True` задає фіксований набір полів.

Тому команда `record.qty = 100` викликає `FrozenInstanceError`.

`to_record(d)` перетворює словник на `Record`. Запис `Record(**d)` розпаковує ключі словника як іменовані аргументи конструктора.

`add_qty(record, amount)` і `change_sku(record, sku)` використовують `dataclasses.replace`. Вони не змінюють початковий об'єкт, а повертають нову копію зі зміненим полем.

### `src/orders/pipeline.py`

Це основний модуль обробки замовлень.

#### `parse(line)`

Функція розбирає один текстовий рядок:

1. Видаляє символ завершення рядка.
2. Ділить рядок за `;`.
3. Перевіряє, що полів рівно чотири.
4. Перевіряє, що обов'язкові поля не порожні.
5. Перевіряє можливість перетворити `qty` на `int`, а `price` на `float`.
6. Повертає словник або `None`, якщо рядок неправильний.

На цьому етапі `qty` ще повертається як рядок. Його остаточне перетворення в `int` виконується під час нормалізації.

#### `process(lines, now)`

Функція приймає готові рядки та значення часу. Вона викликає `parse` для кожного рядка, рахує помилки й додає правильним записам поле `received_at`.

`process` не відкриває файл, не друкує результат, не використовує глобальні змінні й не викликає `time.time()`. Тому за однакових `lines` і `now` вона повертає однаковий результат.

#### Нормалізація

Нормалізація розділена на три маленькі функції:

- `strip_strings` прибирає зайві пробіли з усіх рядкових полів;
- `lower_category` переводить категорію в нижній регістр;
- `to_int_number` перетворює `qty` на ціле число.

Вони об'єднані за допомогою `pipe`:

```python
normalize = pipe(strip_strings, lower_category, to_int_number)
```

Наприклад:

```python
{'sku': ' BOOK-001 ', 'qty': ' 5 ', 'category': ' КНИГИ '}
```

перетворюється на:

```python
{'sku': 'BOOK-001', 'qty': 5, 'category': 'книги'}
```

#### Відбір і агрегація

`keep` створений так:

```python
keep = make_predicate('qty', 'ge', 5)
```

`ge` означає `greater or equal`, тобто `>=`. Предикат залишає записи, в яких `qty >= 5`.

`select_records` будує конвеєр через `map` і `filter`:

- перший `map` викликає `parse`;
- `filter` відкидає значення `None`;
- другий `map` викликає `normalize`;
- останній `filter` застосовує `keep`.

`add_to_groups` додає `qty` поточного запису до суми його категорії.

`aggregate` використовує `reduce`, починаючи з порожнього словника `{}`. Після проходу всіх записів отримуємо словник сум за категоріями.

`pipeline` з'єднує відбір та агрегацію в один повний конвеєр.

### `src/orders/hof.py`

`hof` означає *higher-order functions* — функції вищого порядку. Це функції, які приймають інші функції або повертають функції.

`compose2(f, g)` повертає функцію `f(g(x))`: спочатку виконується `g`, потім `f`.

`compose(*funcs)` застосовує функції справа наліво:

```python
compose(f, g, h)(x) == f(g(h(x)))
```

`pipe(*funcs)` застосовує функції зліва направо:

```python
pipe(f, g, h)(x) == h(g(f(x)))
```

`make_predicate(field, op, value)` створює налаштовану функцію-перевірку. Наприклад:

```python
make_predicate('qty', 'ge', 5)
```

повертає функцію, еквівалентну перевірці `rec['qty'] >= 5`. Операція береться з модуля `operator` через `getattr`.

Це замикання: створена функція пам'ятає значення `field`, `op` і `value` навіть після завершення `make_predicate`.

`make_running_total()` створює функцію-накопичувач. Вона пам'ятає поточну суму в змінній `total`, збільшує її при кожному виклику та повертає нове значення. Для зміни змінної зовнішньої функції використовується `nonlocal`.

`scale(factor, value)` множить число на коефіцієнт і округлює результат до двох знаків.

`curry3(f)` перетворює виклик `f(a, b, c)` на послідовність викликів `curry3(f)(a)(b)(c)`. Кожен проміжний виклик повертає нову функцію, яка чекає наступний аргумент.

### `src/orders/lazy.py`

Цей файл демонструє ліниві обчислення. Генератор не створює всі результати відразу. Він видає наступний елемент через `yield` лише тоді, коли цей елемент запитують.

Генераторний конвеєр складається з трьох функцій:

- `g_parse` читає рядки, розбирає їх і пропускає неправильні;
- `g_normalize` нормалізує записи;
- `g_keep` залишає записи, які пройшли перевірку.

Вони з'єднуються так:

```python
g_keep(g_normalize(g_parse(file)))
```

Файл читається по одному рядку, тому весь його вміст не потрібно зберігати в пам'яті.

`record_stream()` є нескінченним генератором. Він створює записи на основі внутрішнього лічильника. Категорії повторюються по колу, а `qty` змінюється від 1 до 25. Послідовність детермінована, тобто новий генератор завжди створює ті самі значення в тому самому порядку.

`take(n, it)` повертає перші `n` елементів ітератора. Наприклад, `take(3, range(10))` дає `[0, 1, 2]`.

`drop(n, it)` пропускає перші `n` елементів і повертає решту. Наприклад, `drop(3, range(6))` дає `[3, 4, 5]`.

### `src/orders/calculator.py`

Калькулятор представляє арифметичний вираз як дерево об'єктів:

- `Num` — число;
- `Neg` — унарний мінус;
- `Add` — додавання;
- `Sub` — віднімання;
- `Mul` — множення;
- `Div` — ділення;
- `Pow` — піднесення до степеня;
- `Sqrt` — квадратний корінь;
- `Sum` — сума довільної кількості виразів.

Наприклад, вираз `(2 + 3) * 4` представлено так:

```python
Mul(Add(Num(2), Num(3)), Num(4))
```

`Expr = Num | Neg | ...` означає, що вираз може бути об'єктом будь-якого переліченого класу.

`evaluate(node)` використовує `match/case`, щоб визначити вид вузла. Наприклад:

```python
case Add(a, b):
    return evaluate(a) + evaluate(b)
```

Спочатку рекурсивно обчислюються ліва і права частини, а потім їх результати додаються.

Для `Sum` використано розпакування послідовності:

```python
case Sum([head, *rest]):
    return evaluate(head) + evaluate(Sum(tuple(rest)))
```

`head` — перший доданок, а `rest` — решта. Базою рекурсії є порожня сума `Sum([])`, для якої повертається `0.0`.

Також функція обробляє помилки: ділення на нуль, від'ємний показник степеня, корінь із від'ємного числа та невідомий тип вузла.

### `src/orders/impure.py`

Це початковий приклад із побічними ефектами, який потрібен для порівняння з чистим рішенням.

Функція `load`:

- сама відкриває файл;
- друкує рядки;
- змінює глобальні `records` та `errors`;
- самостійно викликає `time.time()`.

Через глобальний стан повторні виклики накопичують дані. Через системний час результат залежить від моменту запуску. Основний конвеєр цей модуль не використовує.

### `demo.py`

Це головний файл демонстрації всіх завдань.

Рядок із `sys.path.insert` додає папку `src` до шляхів пошуку модулів, тому Python може імпортувати пакет `orders`.

У функції `main()` послідовно показано:

1. Детерміновану роботу `process` і підрахунок неправильних рядків.
2. Незмінність `Record`, використання в `set` і як ключа словника.
3. Роботу `compose`, `pipe`, предикатів і незалежних накопичувачів.
4. Конвеєр `map/filter/reduce` та агрегацію.
5. Часткове застосування через `partial` і каррирування через `curry3`.
6. Лінивий генераторний конвеєр, нескінченний потік, `take` і `drop`.
7. Калькулятор, усі типи виразів і передбачені помилки.

Саме в `main()` виконується введення-виведення: відкривається файл, викликається `time.time()` і друкуються результати.

Конструкція:

```python
if __name__ == '__main__':
    main()
```

запускає `main()` тільки тоді, коли `demo.py` запущено безпосередньо. Якщо його імпортувати як модуль, демонстрація автоматично не почнеться.

## Контрольні запитання

### 1. Які побічні ефекти були у вихідному модулі та як їх усунули?

У `impure.py` були такі побічні ефекти:

- `open` — функція сама відкривала файл;
- `print` — функція сама друкувала дані;
- `global` — змінювалися глобальні `records` та `errors`;
- `time.time()` — результат залежав від поточного часу.

У чистому варіанті `parse` працює лише з одним переданим рядком, а `process` отримує готові `lines` і `now`. Вони не виконують введення-виведення й повертають результат замість зміни глобальних змінних.

Файл і час залишилися в `main()`, тому що це межа програми, де нормально взаємодіяти із зовнішнім світом. Завдяки цьому `process(lines, 1000.0)`, викликаний кілька разів, завжди повертає однаковий результат.

### 2. Чому заморожений `dataclass` можна додати в `set`, а звичайний — ні?

`set` і ключі словника потребують хешованих об'єктів. `Record` має `frozen=True`, тому після створення його поля не змінюються, і `dataclass` може створити стабільний хеш.

Звичайний змінний `dataclass` за стандартних налаштувань нехешований. Якби об'єкт можна було змінити після додавання в `set`, його хеш міг би змінитися, і множина більше не змогла б правильно його знайти.

`replace` повертає новий об'єкт зі зміненим полем, тому початковий запис залишається незмінним.

### 3. У якому порядку працюють `compose` і `pipe`?

`compose` застосовує функції справа наліво:

```python
compose(f, g, h)(x) == f(g(h(x)))
```

`pipe` застосовує функції зліва направо:

```python
pipe(f, g, h)(x) == h(g(f(x)))
```

У демонстрації `f` додає 1, `g` множить на 2, а `h` підносить до квадрата. Для числа 3 `compose` повертає 19, а `pipe` — 64. Різні результати підтверджують різний порядок.

### 4. Чому `make_running_total` потребує `nonlocal`, а `make_predicate` — ні?

`make_running_total` не лише читає, а й змінює змінну `total` із зовнішньої функції. `nonlocal total` повідомляє Python, що треба змінювати саме цю зовнішню змінну.

Без `nonlocal` Python вважав би `total` локальною змінною внутрішньої функції, і спроба виконати `total += value` завершилася б помилкою.

`make_predicate` лише читає запам'ятовані `field`, `op` і `value`, тому `nonlocal` там не потрібен.

Кожен окремий виклик `make_running_total()` має власну незалежну суму.

### 5. Які конструкції не можна використовувати в `lambda`?

Тіло `lambda` повинно складатися з одного виразу. У ньому не можна написати звичайні блоки `for`, `while`, `try/except`, оператор `return` або звичайне присвоєння через `=`.

Умовний, або тернарний, вираз дозволено. У роботі він використаний для класифікації кількості:

```python
lambda qty: 'мало' if qty < 5 else 'звичайно' if qty < 20 else 'багато'
```

Для складнішої логіки краще використовувати звичайну функцію `def`.

### 6. Чим відрізняються `map/filter/reduce`, спискові включення та генератори?

У Python 3 `map` і `filter` ліниві: вони обробляють наступний елемент тільки тоді, коли його запитують, і не створюють проміжний список.

Спискове включення одразу обробляє всі елементи та створює готовий список у пам'яті.

Генераторні функції з `yield` теж ліниві, але дозволяють явно описати кілька кроків і умов у тілі функції. У нашому генераторному конвеєрі файл читається рядок за рядком.

`reduce` повинен пройти весь скінченний потік, щоб побудувати остаточні суми. Агрегація не може повернути остаточний результат, доки не перегляне всі записи.

`map` і `filter` є вбудованими функціями Python. `reduce` винесений у модуль `functools`, тому його потрібно імпортувати.

### 7. Чим `functools.partial` відрізняється від каррирування?

`partial` фіксує частину аргументів наявної функції. Наприклад:

```python
to_km = partial(scale, 1.60934)
```

Після фіксації коефіцієнта залишається передати лише число.

Каррирування перетворює функцію з кількома аргументами на ланцюжок одноаргументних функцій:

```python
curry3(make_predicate)('qty')('ge')(5)
```

`partial` зручний, коли потрібно швидко створити спеціалізовану версію функції з уже відомими аргументами. Каррирування зручне, коли налаштування передаються по одному на різних етапах.

### 8. Де в рекурсії база та рекурсивний крок?

У методичці в цьому запитанні згадується функція `total`, але окремого завдання для неї в наданому PDF немає. У цій роботі рекурсія реалізована в `evaluate`.

База рекурсії — це вузол, який можна обчислити без наступного рекурсивного виклику:

```python
case Num(value):
    return float(value)
```

`Num` не має дочірніх вузлів, тому на ньому рекурсія зупиняється. Ще одна база — порожня сума `Sum([])`, яка повертає `0.0`.

Рекурсивний крок розбиває вираз на менші частини. Наприклад, для `Add(a, b)` функція викликає `evaluate(a)` і `evaluate(b)`. Кожен виклик наближає обчислення до числових вузлів.

### 9. Чому нескінченний потік працює з `islice`, а список зависне?

`record_stream()` видає записи по одному й не намагається створити нескінченну послідовність у пам'яті.

```python
islice(record_stream(), 5)
```

запитує лише перші п'ять елементів, після чого зупиняється.

Виклик `list(record_stream())` намагався б отримати всі елементи нескінченного потоку. Він ніколи не завершився б і поступово використовував би все більше пам'яті.

Генератор зберігає поточну позицію. Після завершення він уже не має наступних елементів, тому повторний цикл по тому самому генератору нічого не повертає. Для нового проходу потрібно створити новий генератор.

### 10. Що дає `match/case` і навіщо вузлам `dataclass`?

`match/case` одночасно перевіряє структуру об'єкта та дістає його складові.

```python
case Add(a, b):
```

перевіряє, що вузол має тип `Add`, і відразу отримує поля `a` та `b`.

```python
case Pow(base, exp) if exp >= 0:
```

використовує guard-умову: ця гілка підходить лише для невід'ємного показника.

```python
case Sum([head, *rest]):
```

розпаковує послідовність на перший елемент і решту.

Таку логіку можна реалізувати через `if`, `isinstance` і ручне читання полів, але для цього потрібно кілька окремих перевірок. `match/case` коротко описує всю форму даних.

`dataclass` автоматично створює `__match_args__`. Для `Add` це поля `('a', 'b')`, тому Python знає, що в патерні `Add(a, b)` потрібно розкласти об'єкт саме на ці два поля.

## Що варто коротко сказати на захисті

У роботі вхідні рядки розбираються, нормалізуються, фільтруються за умовою `qty >= 5` і агрегуються за категорією. Основна логіка винесена в маленькі функції, а введення-виведення залишено в `main()`. Незмінний `Record` змінюється створенням нової копії. Композиція, замикання, `partial`, каррирування та генератори демонструють різні можливості функціонального стилю. Калькулятор представляє вираз деревом незмінних вузлів і рекурсивно обчислює його через `match/case`.

У PDF є дві неточності: калькулятор у різних місцях названо завданням 7 і 8, а в пункті 6.3 сказано про чотири генератори, хоча описано лише `take` і `drop`. У роботі реалізовані всі конкретно описані вимоги. Автоматизовані тести та письмовий звіт за умовою не потрібні.
